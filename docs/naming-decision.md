# App naming — decision & runner-ups

## Decision (2026-05-21)

**The app is renamed from Relay to Coax.**

### Why rename

There is already an iOS app called **Relay — HTTP REST Client** on the App Store (<https://apps.apple.com/us/app/relay-http-rest-client/id6760355682>) in the exact same product niche. Direct collision in positioning, not a peripheral name overlap. Pre-launch is the cheapest moment to rename — no domain bought, no Lemon Squeezy product created, no public users.

### Why Coax

Two meanings stack perfectly on the product:

- **Verb** — *to coax a response out of* an API. Gentle extraction is exactly how API debugging feels: probe, adjust, retry, get the shape right.
- **Noun** — short for *coaxial cable*, the original physical-layer data-transmission medium. Direct tech lineage.

Both are on-target without trying. The dual meaning gives the brand two complementary anchors: the verb is the *feeling* of using it (you coax a response), the noun is the *thing* it does (carries data).

- Short, bright, 1 syllable — easy to say, easy to type, easy to remember.
- Logo opportunity is unusually strong: a coax-cable cross-section (concentric circles) is iconic, instantly readable to anyone technical, and visually distinct from every competitor in this space (which all use envelopes, arrows, planet glyphs).
- Tagline writes itself: *Coax a response.*
- No religious weight, no IP risk like Tolkien names, no near-collision like Relay.
- Trade-off accepted: SEO will fight coaxial-cable results in search; the marketing site will need to do the work to rank.

Companion considerations:

- The current icon glyph (two endpoints linked by a bar) literally encoded the *Relay* metaphor. For Coax, the natural redesign direction is concentric circles (cable cross-section). Defer to a Phase 0.5 task — the rename itself can ship without an icon refresh.

## Runner-up collection

Saved here so we don't have to re-derive these if Coax ever needs to be revisited, or if naming a sibling product comes up.

| Name | Vibe | Notes |
| --- | --- | --- |
| **Apostle** | Sent / messenger (Greek) | Strongest *literal* metaphor — *apóstolos* = "one who is sent." Held the decision briefly before Coax surfaced. Religious weight |
| **Stem** | Clean, modern, organic | Strongest logo potential, but generic and crowded (Stem.io, audio stems) |
| **Crux** | Sharp, essential | "The key point." Mostly clear in dev tools, very ownable |
| **Balrog** | Fierce, fun, memorable | LOTR — Tolkien Estate is aggressive on IP, also a Street Fighter character. Probably untrademarkable |
| **Prodigal** | Distinctive, "returns" metaphor | Religious weight; nice "the response comes back" resonance |
| **Malachi** | Sent / messenger (Hebrew) | Same core metaphor as Apostle, lighter religious weight, needs etymology footnote |
| **Silas** | Short, modern, friendly | Paul's traveling companion / messenger. Weakest metaphor link of the set |

Also seriously considered earlier in the brainstorm: **Cadence**, **Riff**, **Presto**, **Brio**, **Lilt**, **Sting**, **Bree**, **Numinor**, **Selah**, **Jubal**, **Patmos**.

## Rejected directions

- **Relay** — collision with existing App Store HTTP client (see above).
- **http.ui** — original placeholder name.
- Anything with **Envoy**, **Helm**, **Forge**, **Loom**, **Yarn**, **Arc**, **Jam** — all heavily occupied by well-known dev tools.
